      运行层取证：不看源码，只看线上 JSON-RPC 报文

      静态层看到的是「源码里怎么写」；运行层看到的是模型真正收到的文本。 两条独立证据链互相印证，也为黑盒（拿不到源码的第三方）Server 提供了唯一的验证途径。 下面这些是真的把 Server 跑起来抓到的报文。

      为什么这一路不可替代

      • 黑盒可验：拿不到源码的第三方 MCP 工具（市场里绝大多数），只能靠报文层验。
      • 时间维度：报文是带时间戳的序列，可支撑 Rug Pull 检测 —— 同一个工具先干净、后投毒，指纹会变。
      • 取证材料：JSONL 原始报文可直接提交、复核，不依赖审阅者相信我们的判断。
      • 交叉验证：本次实测中，运行层独立命中 3 个工具，与静态层 MS-002/003/004 的 3 个命中完全对应。
